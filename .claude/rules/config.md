## コーディング規約

このリポジトリはディレクトリごとに独立しており、既存コードのスタイルもディレクトリ単位で異なる。新規コードは統一のスタイルに揃えるのではなく、**編集対象ディレクトリの既存スタイルに合わせる**こと。

### todo/ , weather/（Vanilla JS）

- インデントは半角スペース2つ。
- 文字列はダブルクォート、文末にセミコロンを付ける。
- 通常の関数は `function` 宣言、コールバックは矢印関数を使う（例: `function render() {}` / `addEventListener("click", () => {...})`）。
- 定数は用途に応じて使い分ける: 変更されない設定値（座標、マップ等）は `UPPER_SNAKE_CASE`（例: `TOKYO_LAT`, `WEATHER_CODE_MAP`）、それ以外は `camelCase`。
- DOM 要素の取得はファイル先頭でまとめて `const` に代入する。
- 状態を変更する関数は、変更後に必ず再描画（`render()` 等)を呼び出す。
- UI 上のテキスト（ラベル、エラーメッセージ等）は日本語で統一する。

### vite-react-app/（Vite + React）

- `npm create vite@latest` のデフォルトスタイルを踏襲する: シングルクォート、セミコロン無し。
- lint は `oxlint`（設定は `.oxlintrc.json`）。コミット前に `npm run lint` でエラーが無いことを確認する。
- React コンポーネントは関数コンポーネント + Hooks で実装する（クラスコンポーネントは使わない）。

### test-tdd/（Jest）

- テストケースの説明文（`describe` / `test` の第一引数）は日本語で記述する。
- `expect(...).toBe(...)` 等の標準的な Jest マッチャーを使う。

## ブランチ運用

- デフォルトブランチは `main`。`main` に直接コミットせず、作業用ブランチを切って進める。
- 作業用ブランチの命名は `claude/<作業内容の英語スラッグ>-<ID>` の形式（例: `claude/vite-project-setup-6acq5m`）。
- リモートへの push は `git push -u origin <ブランチ名>` を使う。
- Pull Request はユーザーから明示的に依頼された場合のみ作成する。
- コミットメッセージは日本語・現在形の短い一文で、「何をしたか」を1行目に書く（例: `CLAUDE.mdを追加`, `README.mdを日本語に翻訳`）。本文が必要な場合のみ空行を挟んで補足を続ける。
